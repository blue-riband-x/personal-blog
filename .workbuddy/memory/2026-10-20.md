## 击穿霓虹街头：从 Godot 工程到线上作品

`D:\coding\battle` 是一个 Manus 生成的 Godot 4.7 工程（原「霓虹裂巷 / Neon Rift Alley」）。
本轮把它改名、署名、清理、导出网页版、推到 GitHub，并接进博客作品模块。

### 工程其实是「两套代码」

- 真正跑的是 `scenes/title_screen.tscn` → `scripts/neon/title.gd`、`scenes/game.tscn` → `scripts/neon/game.gd`。
- `scripts/*.gd`（game/hero/boss/enemy_*/hud/level_data 等 27 个）是模板留下的**横版射击**代码，全无引用。
- 它们引用的 `assets/template/game/**`（31MB 沙漠/要塞美术）同样无用。

### Godot 安装（本机原来没有）

- 版本必须 `4.7.2.stable.official.ed1daf0bf`（`site/game-release.json` 里写死的）。
- **GitHub release 直连只有 ~50KB/s**，换成 `https://gh-proxy.com/` 前缀 ~1MB/s。
- 编辑器 zip（82MB）解压到 `D:\coding\.godot-dl\`；
  导出模板 tpz 有 1.2GB，本地却只用 web 那几个 —— 远程按 range 抽 zip 成员的办法没跑通
  （gh-proxy 对大偏移 range 会挂），最后整包下完只取 `templates/web_*.zip` + 写 `version.txt`，
  放到 `%APPDATA%\Godot\export_templates\4.7.2.stable\`。
- 导出：`Godot_v4.7.2-stable_win64_console.exe --headless --path . --export-release "Web" build/index.html`
  （导出前先 `node web/build-shell.mjs --output web/loading.html` 生成加载壳）。

## 20:05 源码私有化评估

- 需求：不想让别人看源码，但不删 GitHub 仓库。用户选了「私有仓库 + Pro」。
- **实测账号不是 Pro**：对私有测试仓库 `blue-riband-x/csdemo` 调 `POST /repos/.../pages`
  返回 422 `Your current plan does not support GitHub Pages for this repository.`
  → 免费版私有仓库不能发 Pages，直接 PATCH private 会让线上站点立刻挂。
- 结论：先拿 Pro（学生包免费，含私有库 Pages），Pro 生效后再 `PATCH {"private": true}`，
  随后查 `/pages` + Actions + 匿名访问仓库确认 404，异常就翻回 public 重新开 Pages。
