## 统一博客卡片封面尺寸（16:53）

**问题**：列表页里两张卡片的封面大小不一致，封面下方还有大片留空。

**根因**：
1. 封面用的是固定高 `h-28`（112px）+ `md:w-44`（176px），比例 1.57，
   而两张源图都是约 **1.9:1** 的宽图（`rag.jpg` 1117×585、`winter-cat.jpg` 1920×1012），
   被 `object-cover` 硬裁，视觉上就不一致；
2. 卡片高度由左侧文字撑开（标题两行 + 元信息 + 摘要 + 标签行 ≈ 177px），
   封面只有 112px 且顶对齐，多出来的 60 多像素就变成封面下方的空白。

**改法**（`src/components/blog/PostCard.tsx`）：
- 抽出 `COVER_BOX` 常量统一封面尺寸：手机 `aspect-video` 通栏、桌面 `md:w-52` + `md:aspect-[16/10]`。
  **高度全部由 `aspect-ratio` 推导，不再写死 px**，以后换任意比例的图都不会忽高忽低。
- 标题加 `line-clamp-2 min-h-14`（`leading-7` × 2 行 = 56px），保证单行标题也占两行；
- 标签从独立一行挪进「日期 · 阅读时长」那一行（`flex-wrap`），文字块从 ~177px 压到 ~137px，
  和封面 130px 基本齐平，空白基本消失；
- 卡片容器 `md:items-center`，残余高度差变成上下对称的内边距，不再是一侧贴顶一侧留空。

**验证**：`npm run build` 通过；用 `vite preview`（4173 端口）+ 无头 Chrome 截了
1440 / 1100 / 500 三个宽度，封面尺寸一致、无留空。截图在 `.workbuddy/preview/c1-*.png`。
提交 `73be2c9`。

## 作品页三个问题修复 + 全站性能优化（21:00 起）

用户报了三件事：背景视频「完全静止」、底部草地比原版少一大截、发给别人看加载慢。

### 根因：三个问题其实是两个根因

1. **「静止」和「草地少」是同一个原因** —— 视频根本没起来播，画面停在 `poster` 上。
   而那张 poster 是当初用「1440x900 视口截图」截出来的 16:9 裁切图，
   视频真实比例是 **1764x1176（3:2）**，截图时上下各裁掉一条，底部草地正好被切掉。
   用 ffmpeg 重新抽**整帧**首帧，两个症状一起消失。
   教训：**poster 永远抽整帧，不要用视口截图。**
2. **视频起不来的第二层原因** —— GitHub Pages 到国内实测只有 **约 1Mbps**
   （curl 拉 5.2MB 用了 40 秒）。原片 13.3MB / 8.2Mbps，访客网络根本喂不动，
   浏览器就一直停在 poster 上。
3. **React 写 `muted` 的时机可能晚于浏览器首次自动播放尝试**，被策略拦下后不会重试。

### 改法

- 新增 `src/components/AmbientVideo.tsx`（通用装饰视频组件）：在**任何 `play()` 之前**
  先把 `video.muted = true; video.defaultMuted = true` 落到 DOM，再在
  `loadeddata` / `canplay` / `canplaythrough` / `visibilitychange` /
  首次 `pointerdown|touchstart|keydown` 时补播，所有 `play()` 的 reject 静默吞掉。
  `BlogHero` 与 `WorksBackdrop` 都改用它，不再各写一遍。
  支持 `sources: [{ src, media }]`，按媒体查询分档。
- 裁切重心改 `object-[68%_100%] md:object-[50%_100%]`：**压到底部**，
  只牺牲上方纯黑天空，草地完整保留。
- 路由懒加载（`App.tsx`）＋ `Suspense` 兜底。
