   否则 `/assets/*.js` 指向域名根直接 404。

## 作品详情放大视图（音乐盒子入作品模块）

音乐盒子已作为「游戏玩具」首项接入，点任意作品卡片会弹出居中的像素风详情面板
（上图 / 下文 / 最下面「立即体验」）。这套结构对整个作品模块通用。

### 数据结构（`src/lib/works.ts`）

`WorkItem` 新增 `gallery` / `description` / `link` / `linkLabel` / `meta`，
并配套两个兜底函数 `workGallery()`（没配图退回 cover）和 `workDescription()`
（没写简介退回 summary）。占位作品因此也能打开详情，只是不渲染「立即体验」。

### 组件拆分

- `CoverArt` / `Scanlines`：卡片与详情共用的封面渲染 + 扫描线。
- `WorkGallery`：**不是轮播图**。每张图常驻同一层，只按离当前张的
  环形距离（`offsetOf`）改 `translateX / scale / opacity / blur`，
  所以翻页看到的是「中间这张退到旁边、旁边那张顶上来」。
- `WorkDetail`：浮层本体，`index` 受控于此，键盘 ←/→ 由它统一接管；
  调用方用 `key={work.id}` 挂载，换作品时索引自动归零。
- `WorksShowcase`：`activeId === null` → 分类展开 → `detail` 三层状态，
  网格那层挂 `inert`（不可点、不可 Tab、读屏跳过）。

### 两个坑

1. **`-translate-y-1/2` 和 `active:translate-y-[2px]` 写的是同一个
   `--tw-translate-y`**：箭头一按下就从 -50% 掉到 +2px（约 22px），
   `mouseup` 时指针已经不在按钮上，`click` 根本不触发
   （事件流实测：mousedown→下一张，mouseup→图片，click→DIV）。
   修复：外面套 `absolute inset-y-0 flex items-center` 做居中，按钮只留位移。
2. **中间那张的宽度占比决定了邻居能露多少**：邻居贴在框架边缘被裁，
   露出的那一条恒等于 `(1 - 占比) / 2`。手机试过 90% → 只剩 18px、
   基本看不见邻居，退回 **88%**（22px）；框架 aspect 必须跟着配
   `1.6 / 0.88 = 20/11`，否则 `object-cover` 会裁掉左右两边。
   桌面 72% → 22/10。这条链上三个数（宽度占比 / 框架 aspect / 露出的条）互相绑定。

### 素材

`public/works/earworm/01~03.webp`，从 `music-play/docs/screenshots/` 的
drums / synth / bass 截图转的，1600×1000（16:10），17~22KB。

## 作品页三个分类按钮改为页面居中

原来是桌面贴左（`left: 7%`、不做水平居中），移动端已经是 50%。改成两者统一
`left: 50%` + `translate(-50%, -50%)`，**顺带把 `left`/`transform` 的条件分支删掉了**——
现在三颗按钮始终在同一条垂直中线上，选中时只有 `top` 在变，横向零位移，
滑向顶部的过程反而更干净。实测桌面 1440×900 三颗按钮 cx=720，移动端 cx=195。

## 创意设计加入「夏日坡道」，作品图区开始支持视频 / 竖幅

用户给了 `E:\下载\夏日坡道_9x16.mp4`（756×1344、5.18s、7.9Mbps、5.1MB），
要求放进 OSS 一个专门的目录、作为「创意设计」第一项。

### OSS 目录约定

新建 `works/design/`，**创意设计这个分类的视频和图片都放这里**，
`media-src/works/design/` 是仓库内的源文件备份（和 `media-src/videos/` 一个道理）。

`scripts/oss-upload.py` 顺手重写了：**目录结构即对象键**（`media-src/**` → `**`），
不再维护写死的 FILES 列表，新增素材丢文件进 media-src 跑一遍就行。
加了 `--only works/design` 做增量上传，跳过隐藏文件（两遍编码留下的 `.p-0.log`）。
Content-Type 仍然显式写死在一张表里 —— OSS 会把 jpg 猜成 octet-stream。

### 视频压缩

5.1MB → **1.8MB**，756×1344 不变，2-pass 2600k + AAC 128k + faststart。
先试 1400k，SSIM 只有 0.968，块效应在天空渐变上肉眼可见；2600k 时 SSIM 0.980，
抽帧对比（左编码/右原片）看不出差别，就停在这里。**动漫类素材的 SSIM 上不去，
别死磕 0.99**，抽帧对比更靠谱。

### 代码改动

- `WorkItem` 新增 `aspect?: "wide" | "tall"`。竖幅时图区换成 **9:16 立式卡片**：
  框架给高度（手机 `min(44svh,340px)`、桌面 `min(56svh,460px)`），
  卡片用 `aspect-[9/16] h-[92%]` 自己反推宽度。横图那套（`w-[88%]` + 框架比例）不动。
- **竖幅的 `SIDE_SHIFT` 必须单独给 105**（横图是 56）：竖卡只有框架的 1/3 宽，
  按 56% 推会出现「邻居一半藏在当前张后面」，推到 105% 才是三张并排摊开。
- `CoverArt` 按扩展名识别视频（`.mp4/.webm/.mov`），直接复用 `AmbientVideo`
  处理自动播放（**别自己写 `<video autoPlay muted>`**，静音时机那条坑还在）。
  另加 `fit="contain"`：不匹配比例的素材完整显示，底下垫一张同画面 `blur-xl opacity-55` 的虚化层。
- **页码从图区里挪到图区正下方**：竖屏素材占满整张卡的高度，页码压在
  `bottom-2` 一定会盖住画面主体（手机上直接压在人物腿上）。
- 卡片右上角给含视频的作品加了个「视频」角标（新 `PLAY` 像素图标）。
  第一版放左下角，**触屏上摘要默认是显示的，角标直接压在摘要文字上**，挪到右上才干净。
